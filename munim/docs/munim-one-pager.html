Munim

An AI agent for merchant payout complaints. It finds which deduction went wrong, fixes what the rules allow, and replies in the merchant's language.

Paytm hackathon · 14 Nov 2026
One engine, two front doors:
support team and shop owner

1The problem

When a merchant says their money is wrong, support has to find which deduction caused it, then get it reversed. That is slow because:

  • one payout mixes sales, fees, device rent, refunds and loan instalments 1
  • complaints come in many languages
  • support chatbots answer questions, but cannot fix money
  • one fault across many merchants is still fixed ticket by ticket
1.64 croremerchant device subscriptions at Paytm, Q2 FY27 2

2Team side · a support teammate brings the complaint

  1. UnderstandAI reads any Indian language, typed or spoken
  2. Follow the moneyCode pulls ledger, plans, payouts, other systems
  3. Find the causeCode tests known causes; AI writes read-only SQL
  4. Propose, checkAI proposes a fix; code checks it against 11 rules
  5. ActCode runs fixes; a teammate approves refunds over ₹2,000
  6. Reply, sweepAI replies in their language; code finds others hit
Example (fictional): Lakshmi Tiffins writes in Telugu. Two rent plans bill one Soundbox: 5 extra debits, ₹2,495. The extra plan is cancelled, the refund waits for a teammate, and the sweep finds 6 more merchants (₹8,681). Live models: 11 s.

AI proposes, code decides, a teammate approves larger amounts.

3Merchant side NEW · the shop owner asks Munim from their phone

The owner can ask what went wrong, follow an issue, and sometimes get it solved with no ticket. They must not get the team's data or powers, so the same engine sits behind four gates, all enforced in code. Nothing typed in chat and nothing the AI writes can widen access.

Who · loginA signed login token (OTP) sets the shop. Ids typed in chat are ignored.
See · data lensOnly this shop's data. Risk reasons become "routine safety review".
Do · action lensBooks pickups, sends KYC links. Refunds and releases wait for a teammate.
Say · reply checkEach reply is checked for other shops, risk reasons, internal words, limits.

Same question from Royal Electronics (fictional): "My payout has not come. Where is my money?"

Built with

  • React + Vite, FastAPI, LangGraph
  • Gemini + Sarvam (languages, voice)
  • Pydantic checks every AI output
  • SQLite ledger; YAML file per source
  • Offline mode, same safety rules

Tested

244 automated tests, no live AI calls

Merchant side: forged token, another shop's case, risk words never shown, refunds never run alone, pickup self-serves, rate limit.
