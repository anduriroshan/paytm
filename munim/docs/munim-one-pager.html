1The problem

A merchant says money is missing from a payout. Someone has to find which deduction caused it, check it against device, pickup and plan records, and reverse it if it is wrong. Recent posts show where this still fails:

  • one payout mixes sales, fees, device rent, refunds, chargebacks and loan instalments 1
  • rent is still cut after the Soundbox went back or stopped working 3–6
  • merchants wait a month or more; tickets get closed unsolved 6, 8
  • many separate posts describe the same fault 3–6

Scope: deductions from the payout: device rent, loan instalments, holds and chargebacks. Repairs, pricing and dispute decisions go to their own teams.

2What already exists

Answering merchants is already well covered:

  • Paytm's AI reportedly answers 10M+ customer queries a month 10
  • Paytm's AI Soundbox gives voice help and payment updates in 11 languages 11
  • Paytm says it uses AI for merchant onboarding and servicing, and is building merchant agents 12
  • Sep 2026: Razorpay, Cashfree, PayU, BharatPe and Pine Labs announced merchant agents; some chase refunds and chargebacks, with a person signing off money moves 13
Where Munim fits. The posts below fail one step after the answer: checking a cut against device, pickup and plan records, stopping it, and finding other shops hit the same way. We don't know Paytm's internal tools; we used public information only.

4Team side · a support teammate brings the complaint

  1. UnderstandAI reads any Indian language, typed or spoken
  2. Follow the moneyCode pulls ledger, plans, pickups, payouts
  3. Find the causeCode tests known causes; AI writes read-only SQL
  4. Propose, checkAI proposes a fix; code checks it against 11 rules
  5. ActCode runs fixes; a teammate approves refunds over ₹2,000
  6. Reply, sweepAI drafts the reply, a teammate sends it; code finds others hit
Example (fictional, demo case S1): Sharma Kirana Store says in Hindi that ₹499 rent is still cut after the Soundbox went back. Code finds the pickup done on 12 Sep and 2 rent debits after it. Rent is stopped and ₹998 refunded. If the AI believes the merchant's "3 months" and asks for ₹1,497, the rules cut it to ₹998, what the ledger proves. The Hindi reply waits for a teammate to send. The sweep finds 36 more shops with the same fault (₹32,029) for a teammate to review (see 5).
Where AI is usedReading complaints in Indian languages and voice, proposing a fix, drafting replies, and writing read-only SQL when no known cause fits.
Where it is notPulling records, testing known causes, the 11 rules, every amount, running fixes, the sweep and merchant access are plain code. AI output never moves money on its own.

AI proposes, code decides, a teammate approves larger amounts and sends every reply.

5Same fault, other shops · found before they complain

Owners hit by the same fault each post alone 3–6. Once a complaint proves a fault, code runs that test on every other shop and rules out lookalikes.

Each fix passes the 11 rules and waits for a teammate, who reviews shop by shop with proof; approval re-checks, so none is paid twice. The shops are planted in the fictional demo data; the test is the same code that checked the complaint (under 25 ms). Not swept: holds, and causes found only by AI-written SQL.

6Merchant side NEW · the shop owner asks Munim from their phone

Owners on page 1 chase pickups and refunds for weeks. Here they can ask what went wrong, follow an issue, and sometimes get it solved with no ticket, without the team's data or powers: four gates, all in code. Nothing typed in chat or written by the AI can widen access.

Who · loginA signed login token (OTP) sets the shop. Ids typed in chat are ignored.
See · data lensOnly this shop's data. Risk reasons become "routine safety review".
Do · action lensBooks pickups, sends KYC links. Refunds and releases wait for a teammate.
Say · reply checkEach reply is checked for other shops, risk reasons, internal words, limits.

Built with

  • React + Vite, FastAPI, LangGraph
  • Gemini + Sarvam (languages, voice)
  • Pydantic checks every AI output
  • SQLite ledger; YAML file per source
  • Offline mode, same safety rules

Tested
